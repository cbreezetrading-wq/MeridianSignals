# Execution reports

One plain-language report per reporting window, generated by `execution/report.ts`:

- `<reportId>.json` — machine-readable, the object `buildReport` returns;
- `<reportId>.md` — the short human-readable version;
- `latest.json` / `latest.md` — copies of the newest report, which the console reads;
- `state.json` — the scheduler's own state: the last report id/time and the last record seq it covered. It decides when the next report is due.

A report is generated by the supervised watcher on `report.intervalHours` (default **6**, a team default, not an owner instruction) and **immediately** after any fill, close, refusal or error. It can also be generated on demand from the authenticated console (`/execution` → "Generate now") or with `bun operator.ts report`.

## What a report is built from

Two sources, and nothing else:

1. the append-only record (`execution/orders.jsonl`), quoted by `seq` in `sources`;
2. a live broker read — account summary, open trades and the closed-trade history — whose own timestamps are recorded next to the figures.

An **order request is not a trade**. `ORDER_REQUESTED` records are listed as requests. Only a `FILL`/`PARTIAL_FILL` record carrying the broker's trade id and fill price, or a trade the broker itself reports, is called a fill. A `FILL`-kind record without that confirmation is listed in `unconfirmedFillRecords` and never counted.

Anything that could not be measured is labelled unmeasured and left `null` — never zero, never guessed. A trade the broker reports closed that the record never closed is listed in `reconciliation.closedAtBrokerNotInRecord` with the broker's P/L, as a gap in **our** record. The broken hash chain (seq 1417, `execution/INCIDENT-2026-11-03-chain-break.md`) is stated on every report rather than smoothed over.

## Delivery

`report.transport` is `none` by default, and with no channel configured every report records the exact sentence

    no notification channel configured — report generated, nothing sent

in the report and in the log, and `notification.delivered` stays `false`. Nothing is sent anywhere. The seam a real channel plugs into is `execution/notify.ts` (`registerTransport`), and choosing a channel is the owner's decision.

## Not in the repository

These files are runtime state, like `orders.jsonl` and `status.json`: they contain live account figures and broker trade ids, so the GitHub export carries this README and the code, not the live reports.
